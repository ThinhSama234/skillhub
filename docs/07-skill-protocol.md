# skillhub Skill Package Protocol

## 8.1 OpenSkills Interoperability Boundary

skillhub's goal is client interoperability: skills installed by the skillhub CLI can be discovered and used by Claude Code / OpenSkills-compatible clients, and vice versa.

### Interoperability Layer (skillhub CLI must be compatible)

- SKILL.md format (frontmatter + markdown body)
- Skill package directory structure conventions (SKILL.md + references/ + scripts/ + assets/)
- Four-level directory priority: skillhub CLI follows the discovery order `.agent/skills` → `~/.agent/skills` → `.claude/skills` → `~/.claude/skills`, consistent with OpenSkills/Claude
- Directory name as lookup key: the installed directory name equals `skill.slug` (i.e., the `name` field in SKILL.md); clients discover skills via directory name
- AGENTS.md `<skill>` descriptor block format: the AGENTS.md index blocks generated by skillhub CLI are compatible with the OpenSkills format

### Server-Side Responsibility Boundary

- The server returns skill metadata (name, description, version) and does not return `location`
- `location` is a client-side local installation path, computed by the CLI based on the installation directory and written to AGENTS.md
- The server does not generate or modify AGENTS.md; that is the client's responsibility

### skillhub Private Extensions (Do Not Affect Interoperability)

- `<skills_system>` / `<available_skills>` block format: skillhub CLI can customize, but must ensure `<skill>` node format is consistent with OpenSkills
- Progressive disclosure (on-demand skill content loading): implemented by skillhub CLI itself
- `.astron/metadata.json`: skillhub private metadata; other clients may ignore it

## 8.2 SKILL.md Specification

Format the server must be compatible with:

```yaml
---
name: my-skill              # required, kebab-case
description: When to use    # required, 1-2 sentences
---

# Markdown body (skill instruction content)
```

Parsing rules:
- `name` and `description` are required fields; missing either causes validation failure
- `name` maps to `skill.slug` (on first publish) and cannot be changed in subsequent versions
- `description` maps to `skill.summary`
- The complete frontmatter parse result is stored in `skill_version.parsed_metadata_json`

Platform extension fields (optional, `x-astron-` prefix):

```yaml
---
name: my-skill
description: When to use
x-astron-category: code-review
x-astron-runtime: claude-code        # reserved
x-astron-min-version: "1.0"          # reserved
---
```

## 8.3 Skill Package Directory Structure

```
my-skill/
├── SKILL.md              # main entry file (required)
├── references/           # reference materials (optional)
├── scripts/              # scripts (optional)
└── assets/               # static resources (optional)
```

Validation rules:
- The root directory must contain `SKILL.md`
- File type allowlist: `.md`, `.txt`, `.json`, `.yaml`, `.yml`, `.js`, `.cjs`, `.mjs`, `.ts`, `.py`, `.sh`, `.png`, `.jpg`, `.svg`
- Single file size limit: 1MB (configurable)
- Total package size limit: 10MB (configurable)
- File count limit: 100 (configurable)

## 8.4 Client Installation Directory Conventions

skillhub CLI follows the directory priority below, maintaining interoperability with OpenSkills/Claude:

| Priority | Path | Description |
|----------|------|-------------|
| 1 | `./.agent/skills/` | Project-level, universal mode |
| 2 | `~/.agent/skills/` | Global-level, universal mode |
| 3 | `./.claude/skills/` | Project-level, Claude default |
| 4 | `~/.claude/skills/` | Global-level, Claude default |

The installed directory name equals `skill.slug` (the `name` field in SKILL.md), ensuring other compatible clients can discover it by directory name.

## 8.5 Relationship with AGENTS.md

- After the skillhub CLI installs a skill, it generates a `<skill>` descriptor block in AGENTS.md via the `sync` command
- The `<skill>` block contains `name`, `description`, and `location` (local installation path), in a format consistent with OpenSkills
- `location` is computed by the CLI from the actual installation path; it is not provided by the server
- The server does not directly generate or modify AGENTS.md; that is the client's responsibility

## 8.6 Client Local Metadata File (skillhub Private Implementation)

The following are private implementation details of the skillhub CLI and are not part of the interoperability protocol. Other clients may ignore this file.

After installation, the CLI writes `.astron/metadata.json` locally:

```json
{
  "source": "skillhub",
  "sourceType": "registry",
  "registryUrl": "https://skills.example.com",
  "namespace": "@ai-platform-team",
  "skillSlug": "code-review",
  "version": "1.2.0",
  "installedAt": "2026-03-11T10:00:00Z",
  "sha256": "abc123..."
}
```

## 8.7 Version Resolution Rules

The skillhub native CLI supports full namespace coordinates:

```
install @team/my-skill              → latest published version (typically resolved via `latest_version_id` / published pointer)
install @team/my-skill@1.2.0        → exact version
install @team/my-skill@latest        → equivalent to no version number (system-reserved tag, read-only)
install @team/my-skill@beta          → beta tag (custom tag)
install my-skill                     → equivalent to @global/my-skill
```

ClawHub CLI uses canonical slugs through the compatibility layer:

```
clawhub install my-skill             → latest version of @global/my-skill
clawhub install team-name--my-skill  → latest version of @team-name/my-skill
clawhub install my-skill@1.2.0       → exact version of @global/my-skill
```

## 8.8 Coordinate Mapping and ClawHub CLI Compatibility

skillhub internally uses `@{namespace_slug}/{skill_slug}` coordinates; the ClawHub CLI uses a single slug. For mapping rules, see `00-product-direction.md` section 1.1.

The local directory name after installation always uses `skill.slug` (without the namespace prefix), ensuring interoperability with OpenSkills/Claude-compatible clients.

| skillhub Coordinate | ClawHub Canonical Slug | Local Installation Directory Name |
|---|---|---|
| `@global/my-skill` | `my-skill` | `my-skill/` |
| `@team-name/my-skill` | `team-name--my-skill` | `my-skill/` |

Note: Installing skills with the same name from different namespaces locally will cause directory name conflicts. The skillhub CLI should detect conflicts at installation time and prompt the user to choose an installation directory or use an alias.
